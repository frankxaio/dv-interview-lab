# Review: data/solutions/gemini-coding.json (hwinterview-076..103)

Reviewer: Claude. Scope: 28 LeetCode-style Python solutions generated by Gemini (agy), the test harness
`scripts/check_coding_examples.py`, and the `is_algorithm` classification in `scripts/build_questions.py`.

## Verdict

**The code is correct; some illustrations were wrong.** All 28 entries solve the LeetCode problem named in the
question title (number and title match). All 28 Python solutions are correct: each was run against a brute-force
reference on thousands of random inputs (or every input up to a size limit) and none failed. The stated time and
space complexities are right, except one aside about sort memory (084). Six entries had errors in their worked
examples or prose (wrong bitmasks, wrong trace indices, a trace that skips a step the code takes, wrong
hardware bit counts). Those are fixed and each one is marked "> Reviewed and corrected by Claude." None of the
entries contains Mermaid or WaveDrom. Every illustration is a Markdown trace table, and each was checked against
what the code actually does.

The harness's expected values are all correct (checked against the LeetCode definitions and brute force).
Every one of the 28 ids is tested and nothing is skipped. It did have gaps, though: for three problems, a
plausible wrong solution passed the harness. New assertions now reject those wrong solutions.

Validation after the fixes:
- `python3 scripts/check_solutions.py data/solutions/gemini-coding.json` gives 28 entries, 0 errors, 0 warnings.
- `python3 scripts/check_coding_examples.py` gives 28/28 PASS.
- Random tests: `/tmp/claude-35304/review-coding/fuzz.py` passes for all 28.

## build_questions.py classification (`is_algorithm`, line ~255)

`is_algorithm = "https://leetcode.com/problems/" in cur` is checked only inside `parse_hw_bank`, against the
question title. In `data/questions.json` it affects **37 questions: hwinterview-067 through hwinterview-103.**
All 37 are now type `coding`, language `python`, category `Coding & Scripting`.
- 067–075 are LeetCode bit-manipulation problems (#136, #137, #190, #191, #201, #231, #260, #268, #287). These are
  in another solutions file and out of scope here, but the classification is correct.
- 076–103 are the 28 reviewed here.
- **No misclassification.** Every question with a LeetCode link is an algorithm problem. The neighboring non-algorithm
  items (hwinterview-055..066: CDC, AXI, setup/hold, resource pointers) do not contain the link and stay `concept`/`text`.
  The other three `python` questions in the bank (cn-partial-013, cn-partial-025, cracking-dv-097) come from other
  rules, not this one.

Related parser issues (not edited; reported only):
- **Subsection headings leak into answers.** The source uses indented `  ### Arrays and hash tables`-style
  subsection headings. These match neither the `## ` section regex nor the `  - ` bullet regex, so each one is
  appended to the previous question's `answer`. As a result, the `answer` field of hwinterview-077, 085, 087, 092, 096 and 102 is
  just a stray heading (e.g. `### Arrays and hash tables`, `### Dynamic programming`). The `tags` also stay at
  the H2 section instead of these subsections.
- All 37 LeetCode items get difficulty `Medium` from `guess_difficulty`. On LeetCode, most are Easy
  (#1, #13, #20, #21, #26, #27, #35, #70, #83, #88, #125, #141, #155, #160, #169, #206, #225, #232, #242, #476,
  #704, #705, #706). #15, #54, #146 and #318 are Medium.
- hwinterview-063..066 are resource pointers rather than questions. SOLUTION_GUIDE says to skip those.

## Minor issues left alone

- 090: the complexity note says fast catches slow "in at most C ≤ N steps". This ignores the time slow needs to
  reach the cycle. Overall O(N) is still right.
- 097: the follow-up calls the single-stack difference trick "O(1) space". The stack still holds N entries; only
  the extra min-tracking storage is O(1).
- 087: the follow-up labels LeetCode #678 "Wildcard matching". The problem is actually "Valid Parenthesis
  String", and "Wildcard Matching" is #44. The description of the method itself is correct.
- 084: the trace table merges several `left += 1` steps for i=0 into one row. The result is still correct.
- 101: "sentinel -1 prevents false matches for key 0". Sentinels are never compared anyway, so this is harmless
  but misleading.
- 079 and 089: the explanation says "if len ≤ 1 return", but the code only special-cases empty input. Both
  behave correctly.
- All solutions use `### Code` + `### Complexity` sections, as the guide requires for coding questions. None has
  Mermaid or WaveDrom, which is fine for algorithm questions, where the guide calls for trace tables.
