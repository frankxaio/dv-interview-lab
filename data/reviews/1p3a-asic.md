# Review: data/manual/1p3a-asic.json (21 questions)

Reviewer: Claude (senior ASIC DV review). Simulator: Synopsys VCS T-2022.06 (`vcs -full64 -sverilog -assert svaext`). All testbenches ran in fresh directories under `/tmp/claude-35304/review-1p3a/`. Nothing was compiled inside the project.

## Overall verdict

**Usable after correction.** All 8 defects that Codex listed are now genuinely fixed and pass simulation. The audit found further real errors in 13 entries, and all 13 are fixed. The most serious ones:

1. **Q19 (one-hot/one-cold)**: the table and answer gave the one-cold constraint as `~a != 0; (~a & (~a - 1)) == 0;`. With unsized literals and an 8-bit `a`, `a` is extended to 32 bits *before* `~` is applied, so this constraint can never be satisfied. VCS reports `Error-[CNST-CIF] Constraints inconsistency failure`. The LaTeX in the proof was also corrupted (`\n`/`\t` escapes had become `\ne` and `\text`).
2. **Q14 (associative array of queues)**: the answer claimed that `function void f(int tbl[string][$])` is illegal. It is legal, and VCS compiles and runs it.
3. **Q15 (static task vs task static)**: the answer field still taught `task static` inside a class as valid with shared locals. That contradicted the corrected solution and IEEE 1800-2017 §8.6.
4. **Q17 (DPI)**: the answer said an asynchronous C thread can call into SV after `svSetScope`. The code never demonstrated the scope switch that the question is about.
5. **Q13 (array locators)**: the table marked the `with` clause as optional for `find_first`/`find_last` (VCS: `Error-[SV-MWC]`). It also called reading `q[0]` on an empty queue a fatal error, but the read actually returns the default value silently.
6. **Q7 and Q10 waveforms** contradicted the RTL and text. The Q11 waveform had no defined timing model.

The question order and identities are unchanged. Every solution still starts with `> Generated by Gemini via agy.`, and the 8 `> Corrected by Codex.` lines are kept. `scripts/check_solutions.py` reports 0 errors and 0 warnings. As instructed, the file was re-serialized with `json.dump(ensure_ascii=False, indent=1)`; the original used indent 2, so the whole-file whitespace diff is expected.

Note on the Codex brief: its data-type list is confused. VCS confirms the IEEE classification. `bit`, `byte`, `shortint`, `int` and `longint` are 2-state (an uninitialized value reads 0, and X/Z assigned to them becomes 0). `logic`/`reg`, `integer` and `time` are 4-state (default x), and `wire` is 4-state (default z).

## Minor issues left alone

- Q1: "In-order requires a blocking cache" and "whole-chip IPC drops to 0" are simplifications. Real in-order cores can do hit-under-miss and stall-on-use.
- Q5: the coverage plan is prose only; no `covergroup` code, although the prompt mentions covergroups. The assertions and plan are correct.
- Q6: "receiver-side placement is the industry first choice" is debatable. Source-side placement with a secondary always-on rail is also common.
- Q7: `language` is `verilog` but the code is SystemVerilog (the prompt allows both). The glitch pitfall wording is loose.
- Q9: "PLRU miss rate only 1–2% worse than LRU" has no source.
- Q10: the 8–12 / 4–6 cycle latency figures are rough.
- Q16: the prompt asks about capturing handles from `fork…join_none`; the example uses a nested `join_any`. Code is correct (verified).
- Q21: correct per the LRM. Observed: VCS 2022.06 actually prints `b=1` for the `$display`. The `#0` pitfall says it "often" forces b=1; for this snippet it is guaranteed. The NBA variant prints `a=0, b=0` deterministically, which the text doesn't state.
- Q20: the rewritten prompt is narrower than the source item ("rand vs randc; implement randc manually").
- The file-level `source` cites only thread 132320, but Q11–Q21 come from thread 431605 (cited inside each answer).
