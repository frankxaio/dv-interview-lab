# DV Interview Lab

A local, LeetCode-style practice site for the design-verification interview questions collected on the
Heptabase whiteboard **DV Interview**. Type an answer (or code), press **AI Evaluate**, and Claude Code on
this machine grades it, explains what is missing, and gives an interview-ready answer.

## Run

```bash
./start.sh            # same as: python3 scripts/build_questions.py && node server.js
```

Open <http://127.0.0.1:8080>. Options: `DVLAB_PORT=9000 ./start.sh`, `DVLAB_HOST=0.0.0.0 ./start.sh`
(listen on all interfaces — only on a trusted network, since anyone who can reach it can spend your Claude usage).

Viewing from another computer over SSH:

```bash
ssh -L 8080:127.0.0.1:8080 <you>@<this-machine>
```

Requirements: Node.js ≥ 18, Python 3.10+, and the `claude` CLI logged in. No npm packages.
The browser loads CodeMirror, marked, DOMPurify, highlight.js, Mermaid and WaveDrom from CDNs;
without internet the editor falls back to a plain textarea and diagrams show as source.

## Using it

| Where | What |
| --- | --- |
| Problem list | Filter by topic, source, difficulty, type, status; `/` focuses search; 🎲 picks an unsolved question |
| Description | The question; mark solved/attempted manually |
| Solution | Illustrated model solution (diagrams, waveforms, tables, code) — hidden until you reveal it |
| Notes | Short notes from the original source |
| Submissions | Every saved/evaluated answer with its feedback; reload one into the editor |
| 💡 Hint | Claude gives a nudge without the answer |
| ✦ AI Evaluate (Ctrl/⌘+Enter) | Claude scores 0–10 with a verdict; ≥ 8 marks the question **solved** |

Deep links: `#/p/<id>`, `#/p/<id>/solution`, `#/p/<id>/notes`, `#/p/<id>/submissions`.
Click a diagram to enlarge it.

## How evaluation works

`server.js` runs `claude -p` (stream-json output, no tools, no MCP servers, a short grading system prompt)
with the question, the source notes, the illustrated solution and your answer. Feedback streams to the page
and is saved with your answer in `data/progress.json`. The model picker chooses Opus / Sonnet / Haiku
(default: your CLI default). Your shell alias sends `claude` through the proxy at `127.0.0.1:1055`;
the server sets the same `HTTP(S)_PROXY`/`ALL_PROXY` unless they are already set (`NO_CLAUDE_PROXY=1` disables it).
Override the binary with `CLAUDE_BIN=/path/to/claude`.

## Content

| Path | What |
| --- | --- |
| `sources/` | Card text pulled from the Heptabase whiteboard |
| `scripts/build_questions.py` | Parses `sources/`, merges `data/manual/*.json` and `data/solutions/*.json` → `data/questions.json` |
| `data/manual/*.json` | Question sets built from cards and PDFs (each with an illustrated solution) |
| `data/solutions/*.json` | Illustrated solutions for the questions parsed from `sources/`, keyed by question id |
| `data/SOLUTION_GUIDE.md` | The format and illustration rules every solution follows |
| `scripts/check_solutions.py` | Validates solution files (JSON, WaveDrom JSON, Mermaid headers, has an illustration) |
| `data/progress.json` | Your submissions, scores and solved status |

The server reloads `data/questions.json` automatically after a rebuild. Question ids are
`<source>-<number>`; they stay stable as long as the parsed sources don't change.

New solutions identify their author at the top of the revealed Solution tab:
`Completed by Codex` or `Generated by Gemini via agy`. A separate `Corrected by Codex`
line identifies Gemini answers that Codex subsequently corrected. These marks identify
authorship, not a guarantee that every code fragment was simulated. Existing solutions
retain their original text.

After adding solutions, rebuild and check coverage and formatting:

```bash
python3 scripts/build_questions.py
python3 scripts/check_completion.py --require-complete
python3 scripts/check_solutions.py data/solutions/*.json data/manual/*.json
python3 scripts/check_coding_examples.py
```

With the server running, `bash scripts/check_diagrams.sh` renders all diagrams in
headless Chrome. Set `DVLAB_PORT` if the server uses another port. The command fails
if a diagram fails or the browser does not produce a completed check result.

`scripts/check_sv_types.sv` is a simulator regression for the two-state `int` versus
four-state `integer` distinction. Compile it with a SystemVerilog simulator and run
the `check_sv_types` top; it prints `PASS` after checking defaults and X conversion.
